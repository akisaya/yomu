# 日剧台词精读页

把一段日文（台词、信、独白）做成可长期使用的学习页：原文可读、译文可关、长句可拆、词可查。产出是**读物**，不是课件。

## 何时使用

- 用户给出一段日剧台词 / 信 / 独白的来源，要求做成网页或学习资料
- 已有作品首页，需要新增一部剧
- 已有一页需要增补拆解、振假名、译文或修排版
- 用户提供某篇的剧照截图，要求放进页面（走「剧照位」，一页一张）

不适用：只做翻译、只做单词表、只做视频字幕。

## 交付物

```
<repo>/
├── index.html                 作品首页（≥2 部作品时才有）
├── assets/stills/             剧照（可选，一页一张；没有就不建）
├── assets/og/                 分享卡 800×800 JPG，一页一张，供 og:image 用
└── <slug>/
    ├── source.md              本篇原文、译文与出处
    └── index.html             单篇精读页，自包含、无构建、双击可开
```

样张（同仓库，可直接打开对照）：`saikou-no-rikon/source.md` 与 `saikou-no-rikon/index.html`（单篇）、`saikou-no-rikon-2/source.md` 与 `saikou-no-rikon-2/index.html`（另一篇）、`index.html`（首页）。

## 工作流

### 1. 取原文并交叉核对

- 至少两个独立来源（opus / 台词站 / 字幕 / 截图）。逐段比对，只在一致处定稿；分歧处取多数或更可信的版本。
- **原文逐字不动**：送假名、标点（「，」「。」）、段落切分、重复的句式都保留。改动只发生在译文与注释里。
- 记录出处：剧名、年份、集数或 SP、脚本家、播出日期。能定位到视频就带上时间码（`?t=秒`），放在页脚或首屏外链。
- 页脚写明「原文与译文仅供学习研究，版权归原作者及电视台所有」。
- 交叉核对后，先把逐段原文写入该篇目录的 `<slug>/source.md`。每篇文章在各自的 `<slug>/` 中成对保存 `source.md` 与 `index.html`；即使同属一部作品，也不把多篇合进一个 Markdown。已有源档时原位更新，不覆盖无关内容。
- Markdown 源档保存纯原文，不抄页面用的 `<ruby>` 朗读标注。HTML 是展示层，不能成为原文与译文的唯一载体。

### 2. 译，并且校

自己译，不搬网上译本；搬了也要逐句对原文。三个固定坑（都真实踩过）：

1. **名句被挪位**：原文「先具体（牙刷、脚、布丁）→ 再抽象（恋爱变日常）→ 又落回具体（袜子、挠背）」的顺序本身就是论证，很多译本把抽象句挪到段末，逻辑就断了。逐句核顺序。
2. **惯用句直译成错义**：`悲鳴を上げる` 是尖叫，不是「失望」；一个词错，整段的笑点就没了。
3. **补原文没有的词**：`一人ずつ二人で生きていたこと` 不要译成「各自拥有的两个人一起生活过的**回忆**」，加了「回忆」，还把「一人ずつ」与「二人で」的矛盾抹平了。

译文风格：书面、克制、不加解释；信息量不超过原文。有取舍就写进「訳注」，不要塞进正文。

译完后把每个中文段落写回该篇的 `source.md`，与原文按段连续排列、一一对应。之后修改原文、译文或分段时先改 Markdown，再同步同目录的 HTML，避免两处内容漂移。

### 3. 拆成五层

每段一张卡，固定五层（顺序即阅读顺序）：

| 层 | 回答什么 | 写法 |
|---|---|---|
| 骨格 | 这句怎么搭起来的 | 挑全段最难的一句，用 `／` 切块，逐块标成分与修饰关系；不是翻译 |
| 文法 | 读这句时被什么绊住 | 每段 6–8 条；每条 = 句型名 + 该段原句片段（`<em>` 标出匹配处）+ 用法说明。片段逐字取自原文，且是跳回 `#pN` 的链接 |
| 語彙 | 哪些词值得记 | 全篇 45–60 词，按出现顺序，含读音/词性/释义/段号 |
| 役割 | 这段在整篇里干什么 | 讲结构功能（呼应、反转、复现），不复述内容 |
| 訳注 | 哪处翻译有取舍 | 只写中文取舍，不复述文法层讲过的语法点 |

**文法不单列成节**，全部放进所属段落的卡片里。曾经做过独立「文法メモ」，被否掉两次：第一次是只收「接续干净、例句短」的 N4/N3 句型，看起来像练习册；第二次是并进精读后只列句型名和解释，读者想看这个句型在哪句里还得往上翻信纸。**句型必须带着它的原句走。**

挑条目按「读的时候被什么绊住」，不按接续表或 JLPT 级别：文末的半句话（～けど。／体言止め）、隔一整句的呼应（どうやら～かもしれない）、指代（それ／そう／そんなこと）、嵌套修饰、一个词翻盘的小辞（だって／なりに），都比再讲一遍「～てみる」值得写。骨格讲结构，文法讲用法，訳注讲中文取舍，三层不要复述同一句。

**双向锚点**：信纸段号 `01` 点进该段卡片 `#d1`；卡片里每条原句片段（以及「文法」标签下的 `原文 ↑`）点回 `#pN`（不分段的页面点回 `#LN`）。目标段落用 `scroll-margin-top` 避开吸顶栏，并用一次短暂的左侧朱线闪动示位。

**振假名**：按 N3 密度全篇 60–70 处。只标「汉字认得、读音拿不准」的（下りる、抱えて、出掛けた、日常、喜び、物語）；`月 / 大 / 手 / 君 / 結婚` 这类不要标，标了反而碍眼。密度控制在每两三行一处，留出裸读空间。

**数字必须自洽**：首页、首屏、页脚里的段数/词数要和真实数量一致，用脚本数，不要凭印象写。删掉文法节后不要再写「16 句型」这类计数。

### 4. 搭页面

固定结构，缺一段都会显得单薄：

1. **首屏**：竖排日文标题 + 朱印 + 一句引文（原文 + 译文），必要时加 2–3 个纯文字按钮
2. **手纸**：原文分段，段号兼锚点，逐段中文译文可关；可选原声片段（有片源时优先于朗读）或逐段朗读。**整篇是一口气的独白或一场戏时不分段**——整段一続き，改用行锚点 `#LN`、卡片称「註」，见 `content-schema.md` 的「变体：一続きの台詞」。开头块（宛名 / EPISODE 头）之后可放一张 3:2 剧照——**可选，不是必填**，有合适画面或用户给了截图才加，位置与裁法见 `typography.md` 的「剧照位」
3. **精読**：每段一张 `<details>` 卡，五层折叠；文法层在卡内，每条自带原句
4. **単語帳**：表格 + 搜索（假名/中文）+ 词性筛选；窄屏转卡片
5. **页脚**：出处、影像链接、版权声明、返回作品列表

正文只有三节（手纸 / 精読 / 単語帳）。不要再单列「文法メモ」——那会让读者在两处之间来回翻。

不设测验、不设评分、不设打卡。

「手纸」必须与同目录 `source.md` 的逐段原文和译文一致。新建 Markdown 源档是增量交付：保留仓库中已有的 HTML、原始页面和用户改动，不要用 Markdown 替换它们；只有用户明确要求迁移时，才调整旧文档的格式或位置。

单篇保持**一个 HTML 文件**（内联 CSS/JS，字体走 Google Fonts + 系统明朝体回退）。同一系列到 3 篇以上，再抽出 `assets/yomu.css` 共用，避免样式副本失控。

作品首页：`index.html` + `<slug>/index.html`。链接写 `xxx/index.html` 而不是 `xxx/`——本地 `file://` 打开时目录链接会变成文件列表。

### 5. 排

设计语言：纸色 `#f7f4ec`、墨色 `#211e1a`、朱红 `#b23a2b`、发丝线 `#e2dacc`；日文用明朝体，中文用宋体，标签用等宽；大量留白与细线，几乎没有色块。

具体 token、竖排标题、ruby、折叠卡、进场动画的代码见 `references/typography.md`。三条硬规则：

- **一条左对齐线**：小节标题、条目、栏目都落在同一个左边距上。
- **编号只允许一层**：不要同时给小节、条目、栏目编号；也不要用悬挂栏位（rail）只放一级编号，会留下空槽。
- **默认开着振假名和中文**，用户关掉后记住；改默认值必须同时升 localStorage 的 key。

### 6. 验

见 `references/verification.md`。最少四件事（脚本路径相对本 skill 目录，页面路径相对当前项目）：

```bash
python3 scripts/check_page.py index.html
node scripts/shot.mjs "file://$PWD/index.html" .shot/top.png --width 1440 --height 900
node scripts/shot.mjs "file://$PWD/index.html" .shot/m.png --width 390 --height 844 --selector "#p1"
```

- **390px 必须走 CDP**：`chrome --window-size=390` 会被钳到 500px，看到的不是手机宽度。
- 内联脚本抽出来 `node --check`。
- 交互冒烟：两个开关、词表搜索与筛选、折叠卡；有音声时点播放、拖进度、看时间。
- 目视：振假名不被上边裁切、行末不参差、无横向溢出、段号与正文不错位。

### 7. 分享预览（OG 卡）

微信、Telegram、X 只读 `<head>` 里的 og 标签。没有 `og:image`，或者地址、格式不对，分享出去就只剩一行纯文字。三条硬要求：

- **绝对地址**：`https://akisaya.github.io/yomu/assets/og/<slug>.jpg`。相对路径爬虫拼不出来。
- **JPG 而非 WebP**：抓取端不一定认 WebP，还会按 300×300 的下限判断有没有图。
- **正方形 800×800**：朋友圈、群聊的缩略图按 1:1 裁，16:9 的剧照会被切掉两边。

卡片样式由 `assets/og-card.html` 用同一套纸色 token 排好（`?slug=` 选条目，`?slug=home` 是首页卡），截图后转 JPG：

```bash
node scripts/shot.mjs "file://$PWD/.agent/skills/japanese-drama-line-study/assets/og-card.html?slug=<slug>" \
  .shot/og.png --width 800 --height 800 --wait 500
sips -s format jpeg -s formatOptions 84 .shot/og.png --out assets/og/<slug>.jpg
```

新增作品时在 `og-card.html` 的 `DATA` 里补一条（`series` / `still` / `title` / `sub` / `size`），再往页面 `<head>` 的 `theme-color` 之后写一整块 `canonical` + `og:*` + `twitter:*`。**微信会缓存第一次的抓取结果**，改完用带 `?v=2` 的地址自测，或等缓存过期。

## 文案：首屏摘要的可复用公式

只有用户明确要摘要时才写，且按这个顺序：

> **处境 → 手法 → 三个具体物 → 落点（原句）**

示例（本仓库定稿）：

> 离了婚的男人，写给前妻的信。通篇没有一句“我爱你”——他写猫，写樱花，写烤红薯，把婚姻拆成一张清单：洗手台上并排的牙刷，被窝里碰到的脚，冰箱里不知何时消失的布丁。写完这些，他才问：要不要一起变老。

反面（都被否过）：

- 以时间地点开头（「在目黑川边那间旧公寓里，他坐下来」）——镜头对准布景，不对准人
- 「通篇都是 X，只有 Y」的并列——说了半天没有具体东西
- 直译日语惯用表达（`離婚届を出す` → 「离婚届已经递出去了」，中文不这么说）
- 结尾加一句「这封信很感人」式的评价——把结论替读者做了

用书面语。不要「点进去」「拆到能看见骨头」这类口语或比喻混搭——和明朝体大标题、朱印摆在一起会打架。

## 设计红线（每条都来自实际返工）

- 不要测验 / 自测 / 得分
- 文法条目不要只写「句型名 + 解释」；没有原句片段就是割裂的
- 不要给跳回的整段铺静态色块（像文字被选中）；左侧朱线闪一下即可
- 按钮不加箭头（↓ ↘ ↗）、不加时间码；时间码留在页脚出处里。卡片里的「原文 ↑」是文字链接，不在此列
- 小节标题下不加副句（「一部一部，全文读完。」这类）
- 作品行、栏目的序号去掉；只保留小节号，且与标题同行
- 首屏不放二手解说，要么引原文，要么留白
- 一页只有一条对齐线；不做多级缩进
- 不用 emoji、不用圆角卡片堆叠、不用渐变按钮
- 剧照不是必填：一页最多一张，位置固定在开头块与正文之间；不进首屏、不做通栏封面、不做图集
- 字幕、台标、水印必须先裁掉；有人的照片不做 sepia / 去饱和（肤色会发青）
